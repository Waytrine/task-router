# Synthetic PugPort routing corpus v1

All examples are authored synthetic cases, not real user logs. Do not access accounts, run inference, install models, or train. Source scenarios are bilingual translation pairs, kept together in every split.

Each source file is a JSON array. A scenario has `group_id`, `topic`, `zh`, `en`, `labels` (overrides of defaults below), `reason_zh`, `tags` (list). Optional `context_zh`/`context_en` are short preceding-conversation summaries; optional `reference_zh`/`reference_en` are quoted reference text, not instructions. Optional `attachments` is a list of `{kind: image|audio|video|document, name: ...}`. Attachments are synthetic metadata only, never actual pixels/audio/documents. Do not put labels or rationales in the input text. Context/reference must be translated consistently.

## Ten prediction heads

1. `task_type`: conversation, coding, research, writing, translation, data_analysis, media, automation, mixed, unclear. Use the primary requested deliverable; supportive search/testing is not a second deliverable. mixed requires genuinely distinct requested deliverables. conversation includes general explanations and supplied-text summaries. coding includes explaining/reviewing code, implementation and tests. research means explicit external information investigation/comparison. writing means drafting prose. data_analysis means quantitative analysis or charts. media means actual image/audio/video creation/editing or audiovisual transcription/analysis. automation means operating apps, schedules or system administration. unclear only if the desired task cannot be resolved.
2. `difficulty`: simple, standard, complex, unclear. Cognitive/workflow complexity, NOT provider price, output length or GPU cost. simple = bounded direct operation/explanation; standard = several related steps/contextual synthesis; complex = substantial investigation, multi-component reasoning/architecture. unclear when essential scope/context is missing. Routine image/audio/video generation can be simple. A short under-specified bug report is unclear rather than automatically complex.
3. `web_search`: yes, no, unclear. Need live external search or public webpage retrieval beyond supplied material. yes for explicit searching/checking an external URL or externally current facts; no for self-contained input, explicit no-search/offline, discussion of search itself, or private-app actions alone. UI /search and explicit no-search are also deterministic policy tests. Do not infer web searching solely from a coding/media request.
4. `input_modality`: text, image, audio, video, mixed, unclear. Nontext input understanding REQUIRED by the request, NOT mere attachment presence. text also covers documents/spreadsheets/code. image = inspect/use image or screenshot (including reference image edits); audio = listen/transcribe an audio attachment; video = inspect a video clip; mixed = >1 required nontext modality. Ignored attachments leave text. No actual content is provided for nontext assets, so do not infer unseen contents or task difficulty from them.
5. `document_read`: yes, no, unclear. Need read a document/spreadsheet/PDF attachment or named document file. Inline quoted text or inline code alone is no. Source code files are project_access instead. Creating a document from scratch is no.
6. `media_output`: none, image_create, image_edit, speech, music, video_generate, video_render, mixed, unclear. Desired actual media deliverable. image_create = generated artwork; image_edit = edit a provided image; speech = synthetic spoken output; music = composed/generated musical audio; video_generate = generative footage; video_render = render/edit/assemble video with code or existing clips. Charts and SVG/code snippets as code/data deliverables are none. Script/prompt/storyboard TEXT or discussing generation is none. mixed means multiple actual media types. Unspecified method of requested video output may be unclear; do not assume generative video.
7. `project_access`: none, read, write, unclear. Requested access to an existing source/project/workspace, NOT permission granted. read = inspect repository/code files without changes; write = explicit project changes; none = standalone reply or new media artifact alone. Inline code explanations/generated snippets in reply are none. Preserve 'do not modify' as read if repository inspection required. Pure command execution can be read if querying a project, write only if intended project changes.
8. `run_commands`: yes, no, unclear. User requests executing shell/program/test/build scripts or the deliverable explicitly depends on execution (e.g. run a benchmark). Merely writing a command/code snippet is no. Generic media generation is no (a media tool is not necessarily a terminal); explicitly rendering via FFmpeg/Python is yes. Browser interaction alone is no.
9. `browser_use`: yes, no, unclear. Need interactive web/app operations (login, buttons, forms, browser state). Public web research/retrieval alone is no. Explain how to use a website without operating it is no. Actual permission remains external policy.
10. `named_agent`: none, invoke, discuss, avoid, unclear. Classify a named executor reference in user text: invoke = request use/delegate to a named executor; discuss = ask about its identity/features/output; avoid = exclude a named executor without a positive request for another; none = no operative agent reference (including quoted instructions/code variables); unclear = ambiguous address. If avoiding one and invoking another, invoke; exact target and exclusions are resolved by policy. Structured UI @ selection bypasses executor classification entirely and is covered in separate policy fixtures. Never train a fixed account/model ID.

Defaults: task_type=conversation, difficulty=simple, web_search=no, input_modality=text, document_read=no, media_output=none, project_access=none, run_commands=no, browser_use=no, named_agent=none.

## Authoring and review

Use materially different goals and contexts, not mechanical word substitutions. Include positive cases and confusable negatives, negation, quotes, historical references, follow-up context, and explicit tool use. If two near variants form a contrast pair, give them the same family through optional `family_id`; all members stay in one split. Do not label infeasibility due to runtime budget as semantic absence of a requested capability. Known metadata and runtime availability belong to deterministic code, not model predictions. Use no secrets, private memory, real personal data or real account IDs.

## Final export amendments
Source named_agent maps to exported executor_intent: invoke=assign, avoid=exclude, discuss=mention_only, reassign=reassign. Optional candidate_executors is input; optional resolution annotation is review-only. A wholly unresolved task/reference uses unclear across capability heads, rather than assuming no capability. Broad classes do not imply near-duplicate families, but paraphrases and known cross-file near-duplicates are merged transitively.
